# 밤: 거점과 협동

## 구조 (확정)

- **싱글플레이와 멀티플레이를 따로 구분하지 않는다.** 캐릭터 4명이 항상 있고, 친구가 들어오면 그 캐릭터를 맡는 구조로 본다 (맡는 방식은 [Q26](open-questions.md)).
- 거점은 **옥탑방이 있는 주택**이고, 그 **지하**에서 시작한다 ([세계관과 게임 시작](00-world-and-start.md#거점-확정)).
- **낮은 각자 수색**, **밤은 거점에서 함께**로 나눈다.
- 멀티에서 가장 어려운 실시간 전투·이동 동기화를 낮에서 통째로 없애고, 밤에는 거점 상태, 인벤토리, 건설물 정도만 맞추면 된다.

## 밤에 하는 일 (제안)

- 전리품 정리, 공용 창고 분배, 식량과 약품 배급
- 방어 시설 설치와 제작 (함께 재료를 모아 건설)
- 부상 치료, 휴식, 다음 날 계획(임무 배정)
- 좀비 습격 대응

## 습격 방식 (미정)

| 방식 | 설명 | 난이도 |
|---|---|---|
| 배치형 | 방어 시설 위치를 정해두면 결과를 계산 | 낮음 |
| 선택지형 | 습격 이벤트에서 함께 대응 방법을 고름 | 낮음 |
| 실시간 디펜스 | 호스트가 연산하는 단순한 디펜스 전투 | 높음 |

처음에는 배치형이나 선택지형으로 시작하는 것을 추천.

## 협동 규칙 (제안)

| 항목 | 제안 |
|---|---|
| 인원 | 캐릭터 4명 고정 (**확정**). 사람이 맡지 않은 캐릭터는 NPC처럼 행동 (제안) |
| 밤 시작 | 각자 자기 속도로 낮을 진행하고, 모두 귀환하면 밤 시작. 먼저 온 사람은 거점 정비하며 대기 |
| 접속 | 방 코드 또는 친구 초대 |
| 연결 끊김 | 재접속 시 상태 복구. 낮 플레이는 끊김의 영향을 받지 않음 |
| 선택 충돌 | 투표 또는 방장 결정 (미정) |
| 자원 공유 | 공용 창고 + 개인 인벤토리 (미정) |

## 저장 구조 (제안)

- 거점 데이터(창고, 건설물, 생존자 상태)는 **호스트 기준**으로 저장
- 개인 데이터(인벤토리, 스킬, 레벨)는 **각자 기기**에 저장
- 친구끼리 하는 협동이라 개인 데이터 조작 방지는 우선순위가 낮음

## 네트워크 기술 (제안)

- Unity: Photon Fusion, 또는 Netcode for GameObjects + Unity Relay
- 서버를 직접 운영하지 않는 호스트 방식(P2P)으로 비용을 줄인다

## 개발 순서 (제안)

1. 낮 파트 완성 (이동, 수색, 전투, 귀환)
2. 밤 파트를 싱글로 구현 (거점 관리, 습격)
3. 밤 파트에 협동 접속 추가 (상태 공유부터 시작)
